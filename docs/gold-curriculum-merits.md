# ゴールドカリキュラム：技術選定とメリット総括

## 概要

本ドキュメントは、中小企業向けAI伴走型開発教育「ゴールドカリキュラム」における技術選定の根拠と、各視点からのメリットをまとめたものです。

---

## カリキュラム全体における位置づけ

| ステージ | 技術スタック | ゴール |
|---|---|---|
| ブロンズ | Python + Pandas + Google Colab | データ操縦術、Excel業務の自動化 |
| シルバー | React (Vite) + Supabase + Codespaces + Claude Code | 現場の業務アプリを自作 |
| **ゴールド** | **+ Edge Functions + 外部API連携** | **バラバラなシステムを繋ぐ** |
| プラチナ | LangChain + AI Agent | AI社員による自律化 |

---

## ゴールドの目標

```
「バラバラなシステムを繋ぐ」

・既存システム同士の連携
・外部SaaSとの接続
・業務の自動化
・データの一元管理
```

### 解決する現場の課題

```
【よくある状況】
・予約システム、レセコン、決済端末がバラバラ
・各システムからCSVを出してExcelで集計している
・手作業で転記・照合している
・データが分散して全体像が見えない

【ゴールドで解決】
・システム間をAPIで連携
・自動でデータを集約
・定期レポートを自動生成
・一元管理ダッシュボードを構築
```

## Edge Functions を主軸とする理由

### iPaaS（JENKA, n8n, Zapier等）との比較

| 観点 | Edge Functions | iPaaS |
|---|---|---|
| 学習効果 | ◎ 仕組みを理解 | △ 使い方だけ |
| 自由度 | ◎ 何でも作れる | ○ 用意された範囲 |
| 構築速度 | △ 時間かかる | ◎ すぐできる |
| 運用コスト | ◎ ほぼ無料 | △ 月額課金 |
| 保守 | ○ 自社で対応 | △ ツール依存 |
| 独自ロジック | ◎ 対応可能 | △ 限界あり |

### Edge Functions を選ぶ理由

```
1. カリキュラムの一貫性
   ブロンズ: コードで自動化（Python）
   シルバー: コードでアプリ開発（React）
   ゴールド: コードで連携（Edge Functions）
   → 「コードで解決できる人」を育てる

2. 自律の実現
   iPaaS → ツールに依存する人が育つ
   Edge Functions → 自分で何でも作れる人が育つ

3. コスト優位性
   iPaaS → 月額費用が継続
   Edge Functions → Supabase無料枠内で十分

4. 学習効果
   iPaaS → 「設定の仕方」を覚える
   Edge Functions → 「仕組み」を理解する
```

## iPaaSの位置づけ

### 教える範囲

```
【メイン】Edge Functions + 外部API連携
→ 自分で作れる力を身につける

【補足】iPaaSの紹介（存在と使い分けを知る）
→ 詳細な使い方は教えない
```

### 主要なiPaaSツール（参考情報として紹介）

| ツール | 特徴 | 用途 |
|---|---|---|
| JENKA | 国産、日本語サポート充実 | 日本企業向け |
| n8n | オープンソース、セルフホスト可 | オンプレ対応が必要な場合 |
| Zapier | 海外定番、連携サービス最多 | グローバルサービス連携 |
| Make | 複雑なフロー構築が得意 | 高度な自動化 |

### 使い分けの判断基準

| 状況 | 推奨 |
|---|---|
| 独自ロジックが必要 | Edge Functions |
| 定型的な連携を素早く | iPaaS検討 |
| コストを抑えたい | Edge Functions or n8n（セルフホスト） |
| クラウドNG | n8n（セルフホスト） |
| 技術者がいない現場に導入 | iPaaS |

JENKAで実現できる主要なユースケースは、ゴールドでも実現可能です。

### 経理・人事総務部門

| ユースケース | JENKA | ゴールド | 実現方法 |

| 納品リスト → 週次通知 | ◎ | ◎ | Edge Functions + Slack/LINE API |
| ファイルアップ → 社員通知 | ◎ | ◎ | Supabase Storage トリガー + 通知 |

### 営業・インサイドセールス部門

| ユースケース | JENKA | ゴールド | 実現方法 |

| CRM更新 → スプレッドシート転記 | ◎ | ○ | Edge Functions + Google Sheets API |

**結論：JENKAの活用シーンの約90%はゴールドで実現可能**

## オンプレミス対応（クラウドNGの場合）

### 課題

```
・医療機関など、患者データをクラウドに出したくない
・NASに保存している既存データとの連携
・法規制やセキュリティポリシーの制約
```

### 解決策：ハイブリッド構成

```
【クラウド側】（Supabase）
・予約管理、シフト管理、売上集計
・患者の個人情報を含まないデータ

【オンプレ側】（既存NAS等）
・カルテ、患者基本情報
・既存システムのデータ

【連携】
・患者IDのみをキーにして紐付け
・個人情報はオンプレ側に留める
```

### n8nセルフホストの活用

```
クラウドに抵抗がある場合:
・n8nを院内サーバー/NASにインストール
・データが外部に出ない
・iPaaS的な自動化を社内で実現
```

## 実装例

### 例1：問い合わせ → CRM + Slack通知

```
【トリガー】
Webフォーム送信 → Supabaseに保存

【Edge Function】
1. データをSupabaseから取得
2. Slack Webhook で通知
3. 必要ならGoogle Sheetsにも転記

【コード量】
約50行程度（Claude Codeで生成可能）
```

### 例2：定期レポート自動送信

```
【トリガー】
pg_cron（毎週月曜9時）

【Edge Function】
1. 先週のデータを集計
2. レポート形式に整形
3. LINE or メールで送信

【コード量】
約80行程度
```

### 例3：GPTで問い合わせ返信下書き

```
【トリガー】
問い合わせ登録時

【Edge Function】
1. 問い合わせ内容を取得
2. OpenAI APIで返信案を生成
3. 下書きとしてDBに保存

【コード量】
約60行程度
```

## ゴールドで出来ること・出来ないこと

### 中小企業の業務システム

| 機能 | 対応 |
|---|---|
| 顧客管理（CRM） | ◎ |
| 在庫管理 | ◎ |
| 売上・請求管理 | ◎ |
| 予約システム | ◎ |
| 勤怠管理 | ◎ |
| 承認ワークフロー | ◎ |
| レポート・ダッシュボード | ◎ |
| 外部システム連携 | ◎ |
| LINE/メール通知 | ◎ |
| AIアシスタント | ◎ |

**→ 中小企業の業務システムは100%カバー可能**

### 出来ないこと・苦手なこと

| 出来ないこと | 理由 | 代替案 |
|---|---|---|
| ネイティブアプリ | React = Webアプリ | PWA or React Native |
| 超高負荷処理 | Edge Functionsの制限 | 専用サーバー（Heroku等） |
| 動画エンコード | 処理時間・容量制限 | 専用サービス |
| 大規模ML推論 | GPUが必要 | 外部AI API |
| 完全オンプレ | Supabaseはクラウド | n8n + セルフホストDB |

**→ ただし、中小企業の業務では上記が必要になることは稀**

## まとめ

### ゴールドの本質

```
「バラバラなシステムを繋ぐ力」を身につける

・Edge Functions + 外部API で自由度高く実現
・iPaaSの存在は知りつつ、依存はしない
・コストを抑えながら高度な連携を実現
・オンプレ対応も可能（ハイブリッド構成）
```

### この構成の強み

```
React + Codespaces + Claude Code + Supabase + Edge Functions + 外部API

= 中小企業の業務システムにおける「万能構成」

・出来ないことを探す方が難しい
・この構成を習得すれば、ほぼ何でも作れる
・しかも低コスト・低運用負担
```

### カリキュラムの価値

```
ゴールド修了者は:
・外部システムとの連携ができる
・業務の自動化ができる
・データの統合・分析ができる
・iPaaSに頼らず自力で解決できる

→ 中小企業のDXを推進できる人材
```
