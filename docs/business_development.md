## 競合・参考企業分析

### ROIT株式会社

#### 会社概要

```
【基本情報】
・設立：2016年（NTTデータ出身者による創業）
・事業：クラウド専門のシステムインテグレーター
・URL：https://www.roit.co.jp/

【ミッション】
「IT投資効果（Return on IT）の最大化」
→ 社名自体が「Return on IT」から命名

【ビジョン】
「AIクラウドインテグレーターのリーディングカンパニー」

【展開】
・2025年内にシンガポール・上海に現地法人設立予定
・グローバル展開を推進中
```

#### 技術スタック

```
【主要技術】
・Microsoft Dynamics 365（ERP/CRM/SFA/MA）
・Power Platform（Power Apps, Power BI, Power Automate）
・Azure（クラウド基盤）
・生成AI（Microsoft 365 Copilot, Azure OpenAI, ChatGPT）

【特徴】
・Microsoft製品に特化
・エンタープライズ向けの統合ソリューション
・高額なライセンス費用が前提
```

#### サービス内容

```
【7つの事業領域】
1. Dynamics 365 導入・コンサルティング
2. Power Platform 活用支援
3. Azure クラウド構築
4. 生成AI（Copilot/ChatGPT）導入支援
5. BI/データ分析基盤構築
6. IT人材リスキリング・紹介
7. グローバルDX支援

【製造業DXサービス】
・顧客データ、商談、売上、設備稼働状況、品質情報等を可視化
・AIやクラウドを活用した生産効率・品質向上
・3営業日でプロトタイプ提案
・1〜3ヶ月でPoC実施
・「スピード重視で結果にコミット」

【教育・研修サービス】
・Power Platform 研修
・講師は実際の導入コンサルタントが担当
・現場経験に基づいた実践的な内容
```

#### 対象顧客

```
【主なターゲット】
・製造業（特にグローバル展開企業）
・中堅〜大企業
・IT部門を持つ企業
・Microsoft製品への投資が可能な企業
```

### Aratana vs ROIT 比較分析

#### 基本比較

```
項目                ROIT                    Aratana
─────────────────────────────────────────────────────────────
対象顧客            中堅〜大企業            中小企業
IT部門              あり前提                なし前提（共有情シス）
技術スタック        Microsoft中心           OSS中心（Django等）
初期コスト          高い                    低い（無料枠活用）
ライセンス費用      高額（MS製品）          最小限
ローコード          Power Apps              AppSheet
BI                  Power BI                Supabase + 自作
教育アプローチ      リスキリング研修        5段階カリキュラム
講師                実務コンサルタント      （検討中）
```

#### ローコードツール比較

```
【Microsoft Power Platform】
・Power Apps（ローコードアプリ開発）
・Power Automate（ワークフロー自動化）
・Power BI（データ可視化）
・費用：有料（Microsoft 365ライセンス + 追加費用）
・対象：IT部門がある企業

【Google AppSheet】
・ローコードアプリ開発
・ワークフロー機能
・データ可視化
・費用：Google Workspace に含まれる
・対象：中小企業でも導入可能

【共通点】
・非エンジニアでもアプリが作れる
・データドリブンな開発
・業務効率化が目的

【Aratanaの選択理由】
・AppSheetはGoogle Workspaceに含まれる（追加費用なし）
・中小企業が既に使っているツールとの親和性
・ブロンズカリキュラムでの導入ハードルが低い
```

### ROITから学ぶべき点

#### 1. 「投資効果」で価値を語る姿勢

```
【ROITのアプローチ】
・社名自体が「Return on IT」
・「IT投資効果の最大化」を前面に出す
・技術ではなく「効果」で語る

【Aratanaへの示唆】
・「DX教育」ではなく「投資効果」で語る視点
・経営者に響く言葉で価値を伝える
・例：「DX人材育成のROIを最大化」
・例：「IT投資ゼロから始めるDX」
```

#### 2. 実務者が教える研修スタイル

```
【ROITの研修】
・講師は普段から導入コンサルを行う実務者
・現場での導入経験に基づいた知見を提供
・「研修専門講師」ではない

【Aratanaへの示唆】
・カリキュラムの講師も実務経験者が望ましい
・「教科書的知識」ではなく「現場で使える知識」
・Aratana社員自身がDjango+Supabaseで開発している実績
・「共有情シス」での実務経験を教育にフィードバック
```

#### 3. 高速プロトタイピング

```
【ROITのアプローチ】
・3営業日でプロトタイプ提案
・1〜3ヶ月でPoC実施
・「スピード重視で結果にコミット」

【Aratanaとの共通点】
・Phase 2.5「HTMXモックで検証」と同じ発想
・動くものを早く見せて認識ズレを防ぐ
・「業務データ駆動開発」のサイクルと整合

【Aratanaの強み】
・HTMXモックは更に高速（数時間〜1日）
・コード不要で動く画面を作成可能
・中小企業の意思決定スピードに合致
```

#### 4. 段階的な成長パス

```
【ROITの提供価値】
・ローコード（Power Apps）→ プロコード（Azure開発）
・段階的にIT活用度を高める
・リスキリングで社内人材を育成

【Aratanaの提供価値】
・ローコード（AppSheet）→ プロコード（Django）
・5段階カリキュラムで段階的に成長
・最終的に「卒業」できる設計
```

---

### ROITを参考にしない点

```
【対象外とする要素】

1. Microsoft中心のスタック
   → 中小企業にはライセンス費用が高すぎる
   → Google Workspace + OSSの方が適合

2. 大企業向けのサービス設計
   → IT部門がある前提のサービスは不要
   → 「共有情シス」が差別化ポイント

3. グローバル展開
   → Aratanaの対象は国内中小企業
   → 海外展開は現時点で不要

4. 高額なコンサルティングフィー
   → 中小企業には負担が大きい
   → 教育カリキュラムで内製化を支援
```

### 直接サービス（4事業）

```

・受講料（一括 or 月額）

【強み】
・体系化されたカリキュラム

【課題】
・講師の確保・育成

```

#### 2. コンサル事業

```
【内容】
・DX戦略策定支援
・業務分析、要件定義
・技術選定アドバイス
・プロジェクトマネジメント支援

【収益モデル】
・時間単価 or プロジェクト単価
・成果報酬型（オプション）

【強み】
・Aratanaメソッドの知見
・中小企業に特化したノウハウ
・「業務データ駆動開発」の実践経験

【境界の明確化】
・教育事業との違い：個別企業の課題解決 vs 汎用スキル習得
・開発事業との違い：「何を作るか」を決める vs 「実際に作る」
```


##### プラットフォーム比較

```
【Udemy】
・対象：個人学習者（グローバル）
・特徴：誰でも講座を公開可能
・収益：売上の37%〜97%（販路による）
・メリット：即時開始可能、大規模なユーザー基盤
・課題：価格競争が激しい、セール時に大幅値下げ

【マナビDX（経済産業省）】
・対象：DXを学びたい社会人
・特徴：政府公認のDX学習ポータル
・収益：掲載は無料、受講料は講座による
・メリット：DX文脈での認知、助成金対象になりやすい
・課題：掲載審査、他講座との差別化

【JEED（求職者支援）】
・対象：求職者、在職者
・特徴：公的職業訓練との連携
・収益：訓練委託費
・メリット：受講者にとって無料or低額、公的支援
・課題：認定手続き、カリキュラム要件

【JMOOC / gacco】
・対象：社会人学習者（日本）
・特徴：大学・企業が提供する無料講座
・収益：直接収益は限定的（認知拡大目的）
・メリット：信頼性、企業研修への展開
・課題：審査あり、制作コスト
```

##### 展開パターン（推奨：パターンB）

```
【パターンA：フル公開】
・ブロンズの全内容をe-ラーニング化
・Udemy等で低価格（1,200円〜2,400円）
・メリット：最大限のリーチ
・リスク：有料カリキュラムとのカニバリ

【パターンB：一部公開（推奨）】
・ブロンズの前半（導入編）を無料公開
・後半（実践編）は有料 or 対面誘導
・メリット：興味喚起しつつ、対面への導線確保
・例：
  - 無料：Gemini入門、スプレッドシート基礎
  - 有料/対面：SQL入門、Python入門、ER図作成

【パターンC：プラットフォーム別コンテンツ】
・Udemy：実践的なハンズオン講座
・マナビDX：DX概論、Aratanaメソッド紹介
・JEED：求職者向け職業訓練コース（認定取得）
```

### 事業間のシナジー

```
【相互連携】

教育事業 ←→ コミュニティ
├─ 修了者がコミュニティに参加
├─ コミュニティでの質問が教材改善に
└─ コミュニティメンバーが講師候補に

コミュニティ ←→ フランチャイズ
├─ コミュニティ内で優秀な人材を発掘
├─ フランチャイジー候補のスカウト

フランチャイズ ←→ 教育事業
├─ 教育事業のノウハウをフランチャイズに展開
├─ フランチャイジーからのフィードバックで改善

開発・共有情シス ←→ コミュニティ
├─ 開発パートナーをコミュニティから採用
├─ 修了者企業同士のビジネスマッチング
└─ 成功事例をコミュニティで共有

e-ラーニング ←→ 教育事業
├─ e-ラーニング受講者を対面カリキュラムへ誘導
├─ e-ラーニングのコンテンツを対面研修でも活用
└─ 受講データを教材改善にフィードバック
```

### ERP/CRM/SFA/MA への対応方針

```
【方針】
┌─────────────────────────────────────────────────────────┐
│ 「全部自作」ではなく「適材適所」                         │
│                                                         │
│ ・汎用的なERP/CRM/SFA/MA → 既存SaaSを推奨              │
│ ・自社固有の業務アプリ → Aratanaメソッドで開発         │
└─────────────────────────────────────────────────────────┘

【理由】
・ERP/CRM/SFA/MAは「車輪の再発明」になりやすい
・既存SaaSの方が機能豊富で安定
・開発コスト vs ライセンス費用 → SaaSの方が安い場合が多い
・Aratanaメソッドは「SaaSでは対応できない業務」に集中
```

#### 用語整理

```
ERP：Enterprise Resource Planning（基幹業務システム）
     → 会計、在庫、生産、人事等を統合管理

CRM：Customer Relationship Management（顧客関係管理）
     → 顧客情報、対応履歴、満足度管理

SFA：Sales Force Automation（営業支援）
     → 商談管理、案件進捗、売上予測

MA ：Marketing Automation（マーケティング自動化）
     → メール配信、リード育成、キャンペーン管理
```

#### 各事業での対応

```
【コンサル事業での対応】
1. 顧客の要件をヒアリング
2. 既存SaaSで対応可能か判断
3. 対応可能 → SaaS導入支援（選定・設定・教育）
4. 対応不可 → Aratanaメソッドで開発
5. 混在 → SaaS + 自社アプリの組み合わせを提案

【教育事業での対応】
・SaaSの選び方・使い方は教えない（各SaaSの教材に任せる）
・SaaSと自社アプリの連携方法は教える（シルバー以降）
・API連携の基礎（ゴールド以降）

【開発事業での対応】
・SaaS導入支援は基本的にスコープ外
・ただし、連携開発は対応可能
・例：freee APIと連携した見積システム
・例：HubSpot CRMと連携した顧客ポータル

【共有情シス事業での対応】
・SaaSのアカウント管理・設定変更
・SaaSと自社アプリの連携監視
・SaaSの利用状況レポート
```

```
【想定される指摘】
「Dynamics 365 のような統合ソリューションの方が良いのでは？」

【回答】
┌─────────────────────────────────────────────────────────┐
│                    Dynamics 365                         │
│                                                         │
│  ・ライセンス費用：月額数千円〜数万円/ユーザー          │
│  ・導入期間：3〜12ヶ月                                  │
│  ・カスタマイズ：専門技術者が必要                        │
│  ・対象：IT部門がある中堅〜大企業                       │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│           SaaS組み合わせ + Aratanaメソッド              │
│                                                         │
│  ・費用：無料〜月額数千円/企業                           │
│  ・導入期間：数日〜数週間（段階的）                     │
│  ・カスタマイズ：Pythonで自由に                          │
│  ・対象：IT部門がない中小企業                            │
└─────────────────────────────────────────────────────────┘

→ 規模と予算に応じた最適解が異なる
→ 中小企業には「小さく始めて、必要に応じて拡張」が適切
→ Dynamics 365 が必要になる規模 ＝ 卒業のタイミング
```
