# シルバーカリキュラム：技術選定とメリット総括

## 概要

本ドキュメントは、中小企業向けAI伴走型開発教育「シルバーカリキュラム」における技術選定の根拠と、各視点からのメリットをまとめたものです。

---

## カリキュラム全体構成

| ステージ | 技術スタック | ゴール |
|---|---|---|
| **ブロンズ** | Python + Pandas + Google Colab | データ操縦術、Excel業務の自動化 |
| **シルバー** | React (Vite) + Supabase + Codespaces + Claude Code | 現場の業務アプリを自作 |
| **ゴールド** | + Edge Functions + 外部API連携 | バラバラなシステムを繋ぐ |
| **プラチナ** | LangChain + AI Agent | AI社員による自律化 |

---

## コア技術スタック（シルバー以降）

```
GitHub（Codespaces + Issues/Projects）
    +
Supabase（DB/Auth/Storage/Hosting/Edge Functions）
    +
Claude Code（AI伴走）
```

**この3つだけで開発〜運用まで完結**

## 技術選定の根拠

### 1. Supabase を選択した理由

| 比較対象 | 選択理由 |
|---|---|
| Firebase | NoSQLはAI伴走・保守性でSQLに劣る |
| 自前サーバー | 運用負担が大きすぎる |
| AWS RDS | 設定が複雑、中小企業には過剰 |

**Supabaseの優位性:**
- SQL（PostgreSQL）ベースでAIが扱いやすい
- 認証・ストレージ・ホスティングが統合
- Edge Functionsでサーバー処理も可能
- サーバー管理不要（マネージド）
- 無料枠で学習・小規模運用に十分

### 2. Codespaces を選択した理由

| 比較対象 | 選択理由 |
|---|---|
| ローカル開発 | 環境構築の壁、属人化リスク |
| Cursor | ローカルインストール必要 |
| Antigravity | ローカルインストール必要 |
| Replit | AI機能がClaude Codeほど強力でない |

**Codespacesの優位性:**
- ブラウザだけで完結
- ローカルPCにコードを置かない
- 環境構築不要
- どこからでもアクセス可能

### 3. Claude Code を選択した理由

| 比較対象 | 選択理由 |
|---|---|
| ChatGPT | ファイル直接編集不可 |
| Gemini | ファイル直接編集不可 |
| GitHub Copilot | 補完中心、自律性が低い |

**Claude Codeの優位性:**
- ファイル直接編集・コマンド実行が可能
- 対話しながら開発が進む
- コードの説明・レビューも依頼可能
- 高い自律性

### 4. Next.js / FastAPI を必須としない理由

| 技術 | 不採用の理由 |
|---|---|
| Next.js | 業務アプリにSSR/SEO不要 |
| FastAPI | Edge Functionsで大半カバー可能 |

**シンプルさを優先:**
- 学習コストを最小化
- 必要になったら後から追加可能

## 「PCローカルにコードを置かない」メリット

### 中小企業の現実に対応

```
【従来の問題】
・担当者退職 → 環境構築からやり直し
・PC故障 → コード消失
・兼業エンジニア → 本業PCに開発環境を入れたくない
・セキュリティ → コードが個人PCに散在

【Codespaces + GitHubで解決】
・退職 → 新担当がログインするだけ
・PC故障 → 別PCでログインして継続
・兼業 → ブラウザで作業、PCに影響なし
・セキュリティ → コードは会社のGitHubに集約
```

## 開発ライフサイクル全体でのメリット

### 開発フェーズ

| メリット | 内容 |
|---|---|
| 環境構築ゼロ | ブラウザを開くだけで開始 |
| AI伴走 | Claude Codeが実装をサポート |
| 属人化防止 | 環境がコード化されている |
| どこでも作業 | PC・場所を選ばない |

### テストフェーズ

| メリット | 内容 |
|---|---|
| 環境差異なし | 「私のPCでは動く」問題がない |
| 本番同等環境 | Codespaces内で本番に近いテスト可能 |
| AI支援テスト | Claude Codeにテストコード生成を依頼 |

### デプロイフェーズ

| メリット | 内容 |
|---|---|
| ワンアクション | git push で自動デプロイ |
| 履歴管理 | GitHub上で全履歴が残る |
| ロールバック | 問題があれば即座に戻せる |

### 保守フェーズ

| メリット | 内容 |
|---|---|
| 引き継ぎ容易 | 新担当者はログインするだけ |
| コード理解 | Claude Codeに「このコードの説明」を依頼 |
| 修正即反映 | 小さな修正もすぐデプロイ可能 |

### 運用フェーズ

| メリット | 内容 |
|---|---|
| 監視 | Supabase Dashboardで状況確認 |
| 障害対応 | どのPCからでも即座に対応可能 |
| スケーリング | Supabase側で自動対応 |
| バックアップ | Supabaseが自動管理 |

## アジャイル開発との相性

```
【従来】
要件定義 → 設計 → 実装 → テスト → リリース（数ヶ月）

【この構成】
アイデア → 実装 → デプロイ → フィードバック（数時間〜数日）
```

### 1週間スプリントの例

```
月曜: 現場から「この機能が欲しい」
火曜: Codespaces で実装（Claude Codeと対話）
水曜: Pull Request → レビュー
木曜: マージ → 自動デプロイ
金曜: 現場で使ってフィードバック
```

## DevOps との相性

### 全フェーズがブラウザ + クラウドで完結

| フェーズ | ツール |
|---|---|
| Plan | GitHub Issues/Projects |
| Code | Codespaces + Claude Code |
| Build | GitHub Actions（自動） |
| Test | Codespaces内 + CI |
| Deploy | GitHub Actions → Supabase |
| Operate | Supabase Dashboard |
| Monitor | Supabase Dashboard |

### 「1人でもDevOps」が可能

```
専任チーム不要で実現:
✓ コードレビュー（Pull Request + Claude Code）
✓ 自動テスト（GitHub Actions）
✓ 自動デプロイ（GitHub Actions → Supabase）
✓ 監視（Supabase Dashboard）
✓ 障害対応（どこからでもアクセス可能）
```

## ターゲット企業

### 企業規模
- 従業員: 〜200人程度
- IT体制: 情シス部門なし、または1〜2人

### 対象業種例
- 製造業（町工場、部品メーカー）
- 卸売・小売（中小の問屋、専門店）
- サービス業（介護施設、学習塾、美容室チェーン）
- 建設・不動産（地場の工務店、不動産管理会社）
- 医療（歯科医院、クリニック、動物病院）
- 士業（会計事務所、法律事務所）

### よくある課題
- システムはあるが連携できていない
- 外注すると高い
- 内製できる人材がいない
- 1人情シスの属人化

## まとめ

### この構成の本質

```
「GitHub + Supabase + Claude Code」

= 中小企業が自律してDXを進めるための最小構成
= 専任エンジニアなしでも回せる開発基盤
= ブラウザだけで開発〜運用まで完結
```

### 経営者へのメッセージ

```
「開発から運用まで、会社の資産として管理できます」

✓ コードは会社のGitHubに集約
✓ 担当者が変わっても継続可能
✓ 特定の個人・PCに依存しない
✓ 外注依存から脱却
✓ 小さく始めて素早く改善
```

### カリキュラムの価値

```
教えるのは「ツールの使い方」ではなく
「AIと協働して課題を解決する力」

ブロンズで基礎を身につけ
シルバーで自作アプリを完成させ
ゴールドでシステム統合を実現し
プラチナでAI自律化を達成する

この段階を経て、中小企業の「内製力」が育つ
```
